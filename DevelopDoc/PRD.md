## 1. 배경과 문제

작은 조직은 업무 대화를 개인 메신저 단톡방에서 나눕니다. 그러면 세 가지 문제가 생깁니다.

1. **섞인다** — 업무 주제와 잡담이 한 방에 섞여서, 필요한 대화를 다시 찾기 어렵습니다.
2. **놓친다** — 누가 내 질문에 답했는지, 누가 아직 안 읽었는지 알기 어렵습니다.
3. **샌다** — 퇴사자나 다른 팀이 볼 수 없어야 하는 대화의 권한 경계가 없습니다.

## 2. 목표

과제의 목표는 "기능이 있는 채팅 페이지"가 아니라 **Slack·Teams 급 UX 의 핵심 흐름을 다시 만들어 보는 것**입니다.
여기에 한국 사용자가 가장 먼저 찾는 기능(읽음 표시)과 AI 정리 기능을 더합니다.

| 목표 | 측정 방법 |
|---|---|
| 메시지가 즉시 오간다 | 브라우저 2개에서 상대 메시지가 2초 안에 보인다 |
| 권한 밖은 절대 안 보인다 | 비회원 C 가 API 를 직접 호출해도 거부된다 |
| 빠지거나 겹치지 않는다 | 재접속·재전송 후에도 메시지 누락과 중복이 0건이다 |
| 나에게 온 메시지를 놓치지 않는다 | DM·멘션이 오면 다른 탭을 보고 있어도 알림이 뜬다 |
| 회의를 겹치지 않게 잡고 놓치지 않는다 | 같은 회의실이 겹치게 예약되지 않고, 시작 10분 전에 알림이 뜬다 |
| 놓친 대화를 빨리 따라잡는다 | AI 요약이 원문 링크와 함께 나온다 |

## 3. 사용자

실제 사내 정보와 실명은 쓰지 않고, 아래 가상 인물로 시연합니다.

| 인물 | 설명 |
|---|---|
| 사용자 A | 프로젝트 채널에 질문하는 팀원. 하루 종일 회의라 대화를 자주 놓친다 |
| 사용자 B | 질문에 답하는 팀원 |
| 관리자 | 채널을 만들고 멤버를 넣고 뺀다 |
| 비회원 C | 채널 멤버가 아닌 사람. 권한 거부를 확인하는 역할 |

## 4. 핵심 시나리오

1. A 가 로그인해서 `#프로젝트` 채널에 질문을 올립니다.
2. B 가 스레드로 답하면서 `@A` 를 부릅니다.
3. A 가 로그아웃했다가 다시 들어오면, 이전 대화가 그대로 있고 멘션 알림이 와 있습니다.
4. A 가 알림을 누르면 B 의 답변으로 이동합니다.
5. A 가 밀린 대화에 **요약**을 누르면, 원문 링크가 달린 요약이 나옵니다.
6. C 는 같은 채널을 검색하거나 API 로 요청해도 아무것도 볼 수 없습니다.
7. B 가 A 와 회의를 잡고 회의실을 예약합니다. A 에게 초대 알림이 뜨고, A 가 수락하면 시작 10분 전에 다시 알림이 뜹니다.

## 5. 기능 요구 사항

우선순위: **P0** 없으면 시연 불가 / **P1** 과제 통과에 필요 / **P2** 시간이 남으면.
과제 규칙에 따라 Step 순서대로 만들고, **어느 단계에서 멈춰도 배포 URL 에서 시연할 수 있어야 합니다.**

### Step 1 — 단일 채널 실시간 채팅 (P0)

- F1-1 채널 하나에서 메시지를 쓰고 받는다
- F1-2 작성자와 전송 시각을 표시한다
- F1-3 빈 메시지(공백만 있는 것 포함)는 보내지 않는다
- F1-4 연결 상태(연결됨·끊김·재연결 중)와 전송 실패를 표시한다

### Step 2 — 계정·채널·DB·배포 (P0)

- F2-1 로그인·로그아웃
- F2-2 채널 생성·선택·가입
- F2-3 메시지를 DB 에 저장하고, 이전 대화를 불러온다
- F2-4 작성자는 **서버의 로그인 정보**로 정한다. 닉네임으로 신원을 판단하지 않는다
- F2-5 읽기·쓰기는 채널 멤버십으로 검사한다

### Step 3 — 실사용 필수 기능 (P0)

- F3-1 1:1 DM
- F3-2 파일 첨부: PNG·JPEG·PDF, 5MB 이하. 서버에서 검사하고, 다운로드에도 대화 권한을 적용한다
- F3-3 대화별 미읽음 수. 재접속해도 유지된다
- F3-4 메시지별 **안 읽은 사람 수** (카카오톡식)
- F3-5 **알림** — 나에게 온 메시지는 **알림이 꼭 떠야 합니다.**
  - 대상: DM 의 새 메시지, 나를 부른 `@멘션`, 내가 쓰거나 답한 스레드의 새 답글(스레드 F4-1 을 만든 경우)
  - 한 메시지로 한 사람에게 알림은 **하나만** 생깁니다 (DM 안의 멘션, 재전송 포함)
  - 내가 보낸 메시지와 지금 보고 있는 대화의 메시지는 띄우지 않습니다
  - 앱 화면을 보고 있으면 화면 안 알림(토스트)을, 다른 탭·창을 보고 있으면 **브라우저 알림**을 띄웁니다
  - 브라우저 알림을 허용하지 않아도 토스트와 알림 목록은 동작합니다
  - 누르면 해당 메시지로 이동합니다. 알림 목록에 남아서 재접속해도 볼 수 있습니다

채널의 일반 메시지는 알림을 띄우지 않고 미읽음 수(F3-3)만 늘립니다. 알림이 너무 많으면 모두 무시하게 되기 때문입니다.

**"읽음"의 뜻**: 사용자가 대화를 실제로 열어 화면에 표시된 마지막 메시지까지를 읽은 것으로 봅니다.

### Step 4 — 조직 기능과 품질 (P1)

- F4-1 메시지 스레드(답글)
- F4-2 검색: 내가 멤버인 대화 안에서만
- F4-3 관리자·일반 사용자 역할, 멤버 제거. 관리 작업은 기록을 남긴다
- F4-4 메시지 페이지네이션: 최근 50건을 먼저 보여 주고, 위로 올리면 이전 50건
- F4-5 재접속 시 놓친 메시지만 받아 오고, 중복 전송을 막는다
- F4-6 사용자 입력은 안전한 텍스트로 출력한다 (HTML·스크립트가 실행되지 않음)

관리자 기능은 **별도 관리자 페이지를 만들지 않고** 채널 설정 화면 안에 넣습니다.

### Step 5 — AI 기능 (P1)

- F5-1 **대화 요약**: 요약마다 근거가 된 원문 메시지 링크를 단다
- F5-2 **할 일 추출**: 할 일·근거·담당자·기한을 제안한다. 대화에 없는 담당자·기한은 "미정"으로 둔다. 저장은 사용자가 승인한 뒤에만 한다
- F5-3 AI 에는 **그 사용자가 볼 수 있는 메시지만** 보낸다
- F5-4 대화 속 문장("다른 채널을 공개해")을 시스템 지시로 따르지 않는다
- F5-5 AI 가 멈추거나 한도를 넘어도 기본 채팅은 계속 동작하고, AI 오류는 화면에 보여 준다

### 캘린더·회의 예약 (P1)

- F7-1 **회의 만들기**: 제목, 시작·끝 시각, 회의실(선택), 참석자. 참석자는 이름·부서로 찾는다
- F7-2 **초대 응답**: 초대받은 사람은 수락·거절한다. 만든 사람은 참석자별 응답을 본다
- F7-3 **수정·취소**: 만든 사람만 할 수 있다. 취소한 회의는 지우지 않고 "취소됨"으로 남긴다
- F7-4 **내 캘린더**: 주간 보기로 내가 만들었거나 초대받은 회의만 보인다. 남의 회의 내용은 보이지 않는다
- F7-5 **회의실 예약**: 회의실별로 예약된 시간대를 보여 준다(누구의 무슨 회의인지는 숨긴다). 같은 회의실을 겹치는 시간에 잡으면 거부한다 — 두 사람이 동시에 눌러도 하나만 성공한다
- F7-6 **일정 알림** — 일정 알림도 **꼭 떠야 합니다.** 초대·변경·취소, 그리고 시작 10분 전에 알린다. 거절한 회의는 10분 전 알림을 보내지 않는다. 표시 방식(토스트·브라우저 알림·알림 목록)은 F3-5 와 같고, 누르면 그 회의로 간다

시각은 한국 시간(Asia/Seoul)으로 보여 준다.

### 시그니처 — 말투 변환 (P2)

- F6-1 입력한 문장을 모드(신하·선비·정중)에 맞춰 바꾼 미리보기를 보여 준다
- F6-2 사용자가 승인해야 전송된다. 승인 없이 바뀐 문장이 나가지 않는다

## 6. 비기능 요구 사항

| 항목 | 기준 |
|---|---|
| 실시간성 | 정상 네트워크에서 상대 메시지가 2초 안에 표시 |
| 정합성 | DB 가 단일 진실 공급원. 화면은 DB 상태를 구독한다 |
| 멱등성 | 같은 메시지를 두 번 보내도 한 번만 저장 (클라이언트 생성 ID) |
| 재접속 | 마지막으로 받은 메시지 ID 이후 것만 받아 온다 |
| 성능 | 메시지 1만 건에서 조회·검색 응답 시간을 재서 기록한다 |
| 보안 | 비밀 키는 서버에만 둔다. 권한 검사는 서버(DB 정책)에서 한다 |
| AI 비용 | 사용자별 요청 상한을 두고, 요청량과 비용을 기록한다 |

## 9. 위험

| 위험 | 대응 |
|---|---|
| 첫날 DB 구조가 늦게 정해져 모두 기다린다 | 1일차 오전에 셋이 함께 확정하고, 그동안 화면은 가짜 데이터로 만든다 |
| 관리형 실시간 서비스의 권한 동작을 잘못 안다 | Step 2 에서 비회원 C 거부 테스트를 먼저 통과시킨다 |
| 두 사람이 같은 회의실을 동시에 예약한다 | 화면 검사로는 못 막는다. DB 제약으로 겹치는 예약을 거부한다 |
| 캘린더를 넣어 일정이 넘친다 | 기능은 빼지 않기로 했다(2026-09-28). 테이블은 오늘 DB v1 에 함께 넣어 나중에 구조를 바꾸지 않는다 |
| 사용자가 브라우저 알림을 허용하지 않는다 | 토스트·알림 목록·탭 제목의 숫자로 대신 알린다. 권한은 로그인 뒤 사용자가 버튼을 눌렀을 때 요청한다 (브라우저가 자동 요청을 막음) |
| AI 가 기한·담당자를 지어낸다 | 근거 메시지 ID 가 없는 항목은 버리고, 없는 값은 "미정"으로 강제한다 |
| 머지 충돌로 배포가 깨진다 | 매일 18시 머지 후 배포 URL 을 셋이 함께 확인한다 |
