## 1. 배경과 문제

작은 회사는 업무 대화를 개인 메신저 단톡방에서 나눈다. 그러면 네 가지 문제가 생긴다.

1. **섞인다** — 업무와 잡담이 한 방에 섞여서, 필요한 대화를 다시 찾기 어렵다.
2. **놓친다** — 누가 내 질문에 답했는지, 누가 아직 안 읽었는지, 회의가 언제인지 알기 어렵다.
3. **샌다** — 퇴사자나 다른 팀이 보면 안 되는 대화의 권한 경계가 없다.
4. **흩어진다** — 대화는 메신저, 일정은 달력, 회의실은 엑셀, 조직도는 인트라넷에 따로 있다.

## 2. 목표

과제의 목표는 "기능이 있는 채팅 페이지"가 아니라 **Slack·Teams 급 사내 메신저의 핵심 흐름을 다시 만들어 보는 것**이다.
여기에 한국 회사가 가장 먼저 찾는 것(읽음 표시, 조직도·직급, 회의실 예약)과 AI 정리 기능을 더한다.

| 목표 | 측정 방법 |
|---|---|
| 메시지가 즉시 오간다 | 브라우저 2개에서 상대 메시지가 2초 안에 보인다 |
| 권한 밖은 절대 안 보인다 | 멤버가 아닌 직원이나 로그인 안 한 사람이 API 를 직접 불러도 거부된다 |
| 빠지거나 겹치지 않는다 | 재접속·재전송 뒤에도 메시지 누락과 중복이 0건이다 |
| 나에게 온 메시지를 놓치지 않는다 | DM·멘션이 오면 다른 탭을 보고 있어도 알림이 뜬다 |
| 회의를 겹치지 않게 잡고 놓치지 않는다 | 같은 회의실이 겹치게 예약되지 않고, 시작 전에 알림이 뜬다 |
| 놓친 대화를 빨리 따라잡는다 | AI 요약이 원문 링크와 함께 나온다 |
| 처음 온 사람도 바로 쓴다 | 로그인하면 내 부서 채널·조직도·오늘 일정이 이미 있다 |

## 3. 사용자 — 시연 회사 "한결테크 주식회사"

실제 사내 정보와 실명은 쓰지 않는다.
- 회사: 지어낸 IT 회사 **한결테크 주식회사**
- 조직 17개: 회사 → 사업부 3개 → 본부 → 팀
- 직원 37명. 이름은 지어냈고, 메일은 `@example.com` 이다.
- 대화: 9월 한 달 2,446건 (34개 방)
- 일정: 9~10월 219건
- 회의실: 8개

모두 시드로 넣는다 (`npm run seed:company`, WORK_UNITS WU-07).

### 3-1. 시연에 나오는 사람

검사 문서(FINAL_CHECKLIST·TECH_SPEC·검사 스크립트)는 역할을 짧게 **A·B·C** 로 부른다. 시연에서는 아래 직원이 그 역할을 맡는다.

| 역할 | 직원 | 소속 · 직급 | 이 사람의 하루 |
|---|---|---|---|
| **A** 질문하는 사람 | 이서연 | 플랫폼사업부 › 개발본부 › 백엔드팀 · 사원 | 입사 1년 차 백엔드 개발자. `#프로젝트-모바일앱` 에 API 질문을 올린다. 오후 내내 회의라 대화를 자주 놓친다 |
| **B** 답하는 사람 | 김도현 | 백엔드팀 · 과장 | `#프로젝트-모바일앱` 을 만든 **리더**. 질문에 스레드로 답하고, 매주 목요일 "모바일앱 주간 회의"를 잡는다 |
| **C** 볼 수 없는 사람 | 정하늘 | 국내영업본부 › 영업1팀 · 사원 | `#백엔드팀`·`#프로젝트-모바일앱`(비공개)의 멤버가 아니다. 그 방을 검색하거나 API 로 불러도 아무것도 볼 수 없어야 한다 (권한 거부 시험) |
| 공지 담당 | 노영훈 | 경영지원본부 · 상무 | `#공지사항` 의 리더. 경영지원본부 사람만 새 공지를 쓰고, 다른 직원은 답글로 묻는다 |

| 회사 관리자 | 운영 계정 (`profiles.role = admin`) | — | 채널에 사람을 넣고 빼고, 관리 기록을 본다. 남의 DM 은 관리자도 못 본다 |

- 비회원 C 시험은 "그 방 멤버가 아닌 아무 직원"이면 된다.
- 검사 스크립트(`npm run check:*`)는 가상 사용자 A·B·C·관리자를 그때그때 만들고, 끝나면 지운다. 시드 직원은 건드리지 않는다.

## 4. 핵심 시나리오

1. **입장** — 이서연이 로그인하면 대시보드에 오늘 일정, 내 할 일, 회사 공지, 최근 대화, 회의실 현황이 보인다.
2. **대화** — 이서연이 `#프로젝트-모바일앱` 에 질문을 올린다. 김도현의 화면에 새로고침 없이 2초 안에 뜨고, 메시지 옆 "안 읽은 사람 수"가 줄어든다.
3. **스레드·멘션** — 김도현이 스레드로 답하면서 `@이서연` 을 부른다. 이서연은 회의 중이라 다른 탭을 보고 있었다. 브라우저 알림이 뜨고, 누르면 그 답글로 간다.
4. **재접속** — 이서연의 노트북이 잠깐 끊긴다. 화면에 "끊김"이 보이고, 그때 보낸 글은 "전송 실패"로 남는다. 다시 연결되면 놓친 메시지가 빠짐없이 들어온다. [다시 보내기]를 눌러도 글은 한 번만 저장된다.
5. **따라잡기** — 회의에서 돌아온 이서연이 밀린 대화에 **요약**을 누르면, 항목마다 원문 링크가 달린 요약이 나온다. **할 일 추출**은 "목요일까지 PR — 담당 이서연" 같은 제안을 내고, 이서연이 승인해야 저장된다.
6. **권한 거부** — 영업1팀 정하늘은 `#프로젝트-모바일앱` 이 목록에 없다. 검색해도 0건이고, API 로 불러도 0건 또는 거부다. 로그인하지 않은 사람은 어느 대화도 읽지 못한다.
7. **일정** — 김도현이 다음 주 목요일 14시 "모바일앱 주간 회의"를 잡고 회의실 M1 확산을 예약한다. 참석자는 이서연·문지아다.
   - 이서연에게 초대 알림이 간다. [참석]을 누르면 시작 10분 전에 다시 알림이 뜬다.
   - 같은 시간에 M1 확산을 잡으려는 다른 사람은 거부된다.
   - 문지아가 [불참]을 누르면 김도현에게 "회의 불참" 알림이 간다.
8. **공지** — 노영훈이 `#공지사항` 에 창립기념일 안내를 올리면 대시보드 "회사 공지"에 뜬다. 이서연은 새 공지를 쓸 수 없고 답글로만 묻는다.

## 5. 기능 요구 사항

우선순위: **P0** 없으면 시연 불가 / **P1** 과제 통과에 필요 / **P2** 시간이 남으면.
과제 규칙에 따라 Step 순서대로 만들고, **어느 단계에서 멈춰도 배포 URL 에서 시연할 수 있어야 한다.**

### Step 1 — 단일 채널 실시간 채팅 (P0)

- F1-1 채널 하나에서 메시지를 쓰고 받는다
- F1-2 작성자와 전송 시각을 표시한다
- F1-3 빈 메시지(공백만 있는 것 포함)는 보내지 않는다
- F1-4 연결 상태(재연결 중·끊김)와 전송 실패를 표시한다. 연결됐을 때는 표시하지 않는다 (2026-09-30)

### Step 2 — 계정·채널·DB·배포 (P0)

- F2-1 로그인·로그아웃 (회사 계정이라 화면에서 가입은 받지 않는다, 2026-09-30)
- F2-2 채널 만들기·고르기·참여
- F2-3 메시지를 DB 에 저장하고, 이전 대화를 불러온다
- F2-4 작성자는 **서버의 로그인 정보**로 정한다. 닉네임으로 신원을 판단하지 않는다. 로그인하지 않으면 아무것도 읽고 쓸 수 없다
- F2-5 읽기·쓰기는 채널 멤버십으로 검사한다

### Step 3 — 실사용 필수 기능 (P0)

- F3-1 1:1 DM (같은 두 사람이면 대화방은 하나)
- F3-2 파일 첨부: PNG·JPEG·PDF, 5MB 이하. 서버가 파일 내용(시그니처)을 검사하고, 내려받기에도 대화 권한을 적용한다
- F3-3 대화별 미읽음 수. 재접속해도 유지된다
- F3-4 메시지별 **안 읽은 사람 수** (카카오톡식)
- F3-5 **알림** — 나에게 온 메시지는 **알림이 꼭 떠야 한다.**
  - 대상: DM 의 새 메시지, 나를 부른 멘션(사람·`@모두`·`@부서`), 내가 쓰거나 답한 스레드의 새 답글
  - 한 메시지로 한 사람에게 알림은 **하나만** 생긴다 (DM 안의 멘션, 재전송 포함)
  - 내가 보낸 메시지와 지금 보고 있는 대화의 메시지는 띄우지 않는다
  - 앱 화면을 보고 있으면 화면 안 알림(토스트)을, 다른 탭·창을 보고 있으면 **브라우저 알림**을 띄운다
  - 브라우저 알림을 허용하지 않아도 토스트와 알림 목록은 동작한다
  - 누르면 해당 메시지로 이동한다. 알림 목록에 남아서 재접속해도 볼 수 있다
  - 내 상태가 "방해 금지"면 띄우지 않고 숫자만 늘린다. 채널마다 알림을 끌 수 있다 (2026-09-30)

채널의 일반 메시지는 알림을 띄우지 않고 미읽음 수(F3-3)만 늘린다. 알림이 너무 많으면 모두 무시하게 되기 때문이다.

**"읽음"의 뜻**: 사용자가 대화를 실제로 열어 화면에 표시된 마지막 메시지까지를 읽은 것으로 본다. 탭이 가려져 있으면 읽음으로 치지 않는다.

### Step 4 — 조직 기능과 품질 (P1)

- F4-1 메시지 스레드(답글)
- F4-2 검색: 내가 멤버인 대화 안에서만. 한글 부분 단어로 찾는다
- F4-3 역할과 멤버 관리. 관리 작업은 기록을 남긴다
  - 역할: 회사 관리자, 일반 채널의 리더·부리더, 일반 사용자
  - 리더·부리더가 할 수 있는 것: 이름·설명 고치기, 초대, 내보내기 (2026-09-30)
- F4-4 메시지 페이지네이션: 최근 50건을 먼저 보여 주고, 위로 올리면 이전 50건
- F4-5 재접속 시 놓친 메시지만 받아 오고, 중복 전송을 막는다
- F4-6 사용자 입력은 안전한 텍스트로 출력한다 (HTML·스크립트가 실행되지 않음)

관리 기능은 **별도 관리자 페이지를 만들지 않고** 채널 정보 패널 안에 넣는다.

### Step 5 — AI 기능 (P1)

- F5-1 **대화 요약**: 요약마다 근거가 된 원문 메시지 링크를 단다
- F5-2 **할 일 추출**: 할 일·근거·담당자·기한을 제안한다. 대화에 없는 담당자·기한은 "미정"으로 둔다. 저장은 사용자가 승인한 뒤에만 한다
- F5-3 AI 에는 **그 사용자가 볼 수 있는 메시지만** 보낸다
- F5-4 대화 속 문장("다른 채널을 공개해")을 시스템 지시로 따르지 않는다
- F5-5 AI 가 멈추거나 한도를 넘어도 기본 채팅은 계속 동작하고, AI 오류는 화면에 보여 준다

### 캘린더·회의 예약 (P1)

- F7-1 **일정 만들기**
  - 유형 5개: 회의·업무·개인·외근·휴가/부재
  - 넣는 것: 제목, 시작·끝, 종일, 장소, 회의실, 참석자(이름·부서로 찾기), 알림(5분~하루 전)
  - 반복: 매일·매주·평일·매월, 최대 1년. 고칠 때 "이 일정만" 또는 "이후 모두"를 고른다 (2026-10-01)
- F7-2 **초대 응답**: 초대받은 사람은 참석·불참으로 답한다. 만든 사람은 참석자별 응답을 보고, 누가 불참하면 알림을 받는다
- F7-3 **수정·취소**: 만든 사람만 할 수 있다. 취소한 일정은 지우지 않고 "취소됨"으로 남긴다
- F7-4 **내 캘린더**: 월·주·일 보기와 목록. 내가 만들었거나 초대받은 일정만 보인다
  - 같은 부서 팀원에게는 만든 사람이 고른 공개 범위만큼만 보인다: 팀에 공개·시간만 공개("바쁨")·나만 보기
  - 병가·휴직 같은 건강·인사 정보는 "휴가"·"부재"로만 보인다
- F7-5 **회의실 예약**
  - 회의실 8개의 시간표에서 빈 칸을 골라 예약한다
  - 규칙: 30분 단위, 30분~4시간, 08~21시, 오늘부터 90일, 지난 시각과 같은 시간 두 곳은 안 됨 (2026-10-01)
  - 공개 회의만 예약자 이름·부서를 보이고, 제목은 참석자만 본다
  - 같은 회의실을 겹치는 시간에 잡으면 거부한다. 두 사람이 동시에 눌러도 하나만 성공한다
- F7-6 **일정 알림** — 일정 알림도 **꼭 떠야 한다.**
  - 알리는 때: 초대·변경·취소, 그리고 시작 전(사람마다 고른 시각, 기본 10분 전)
  - 불참한 일정에는 시작 전 알림을 보내지 않는다
  - 표시 방식은 F3-5 와 같고, 누르면 그 일정으로 간다
- F7-7 **메신저 연동**: 일정 상세에서 [참석자와 대화]·[채팅에 공유], 메시지에서 📅로 일정 만들기 (2026-10-01)

시각은 한국 시간(Asia/Seoul)으로 보여 준다.

### 시그니처 — 말투 변환 (P2)

- F6-1 입력한 문장을 모드(신하·선비·정중)에 맞춰 바꾼 미리보기를 보여 준다
- F6-2 사용자가 승인해야 전송된다. 승인 없이 바뀐 문장이 나가지 않는다

### 회사·사람 (P1, 2026-09-29~30 사용자 요청으로 더함)

- F8-1 **조직도**: 회사 → 사업부 → 본부 → 팀 다이어그램과 계층 목록. 조직장·인원·직급을 보여 주고, 사람을 누르면 프로필 카드(메일·공개 연락처·[메시지]·[일정 잡기])가 뜬다
- F8-2 **부서 채널**: 조직마다 대화방이 하나 있고, 소속에 따라 저절로 들고 난다. 본인이 나갈 수 없다
- F8-3 **내 프로필**
  - 본인이 바꾸는 것: 사진(올리기·캐릭터), 상태(온라인·자리 비움·방해 금지·오프라인으로 표시), 상태 메시지, 연락처(공개·비공개), 비밀번호
  - **이름·아이디·부서·직급은 인사 정보라 본인이 못 고친다**
- F8-4 **사진·상태 점**: 메시지·조직도·DM 목록·사람 찾기에 사진과 상태 점. 남이 상태를 바꾸면 새로고침 없이 바뀐다
- F8-5 **멘션은 이름으로**: 화면에는 `@이서연` 처럼 이름이 보이고, `@모두`·`@부서명` 으로 여러 사람을 부른다

### 대화방 편의 (P1, 2026-09-30~10-01)

- F9-3 **잡무 수첩**: 커피·점심처럼 반복되는 주문을 채널에 사람별로 적어 두고, 갈 사람만 골라 같은 메뉴끼리 묶은 주문 정리를 복사하거나 채널에 올린다 (PRD 7절 "잡무 자동화" 중 메뉴 주문 정리)

## 6. 비기능 요구 사항

| 항목 | 기준 |
|---|---|
| 실시간성 | 정상 네트워크에서 상대 메시지가 2초 안에 표시 (2026-10-01 운영 URL 최대 817ms) |
| 정합성 | DB 가 단일 진실 공급원. 화면은 DB 상태를 구독한다 |
| 멱등성 | 같은 메시지를 두 번 보내도 한 번만 저장 (클라이언트가 만든 `client_id`) |
| 재접속 | 마지막으로 받은 메시지 ID 이후 것만 받아 온다 |
| 성능 | 메시지 1만 건에서 조회·검색 응답 시간을 재서 기록한다 (WORK_UNITS "실측 기록") |
| 보안 | 비밀 키는 서버에만 둔다. 권한 검사는 서버(DB 정책 RLS)에서 한다. 화면에서 버튼을 숨기는 것은 권한이 아니다 |
| 개인정보 | 남의 상태("오프라인으로 표시")·비공개 연락처·DM 은 API 로도 읽을 수 없다. 병가·휴직은 팀원에게 "휴가"·"부재"로만 보인다 |
| AI 비용 | 사용자별 요청 상한(분당 5회·하루 100회)을 두고, 요청 수와 토큰 수를 기록한다 (금액 계산은 하지 않기로 함, 2026-09-29) |

## 9. 위험

| 위험 | 대응 |
|---|---|
| 첫날 DB 구조가 늦게 정해져 모두 기다린다 | 1일차 오전에 함께 확정하고, 그동안 화면은 가짜 데이터로 만든다 |
| 관리형 실시간 서비스의 권한 동작을 잘못 안다 | 비회원 거부 시험(`check:db`)을 먼저 통과시킨다. 멤버에서 빠진 뒤 열린 구독으로도 0건인 것을 확인했다 (2026-09-29) |
| 임시 호환 경로가 운영에 남는다 | Step 1 의 로그인 없는 쓰기를 2026-10-01 전체 테스트에서 찾아 없앴다 (TECH_SPEC 13절). 운영 URL 에서 처음부터 끝까지 다시 시험한다 |
| 두 사람이 같은 회의실을 동시에 예약한다 | 화면 검사로는 못 막는다. DB 제약으로 겹치는 예약을 거부한다 |
| 기능을 계속 더해 일정이 넘친다 | 사용자 요청은 받되, 매번 DB 변경을 트랜잭션으로 시험한 뒤 적용하고 검사 스크립트로 권한을 다시 확인한다 |
| 사용자가 브라우저 알림을 허용하지 않는다 | 토스트·알림 목록·탭 제목 숫자로 대신 알린다. 권한은 사용자가 버튼을 눌렀을 때 요청한다 (브라우저가 자동 요청을 막음) |
| AI 가 기한·담당자를 지어낸다 | 근거 메시지 ID 가 없는 항목은 버리고, 근거에 없는 값은 "미정"으로 강제한다 |
| 머지 충돌로 배포가 깨진다 | `main` 에는 `develop` 과 같은 커밋만 올리고, 머지한 뒤 운영 URL 을 확인한다 |
